# Intility PowerPoint Instructions


Follow these instructions strictly. The Intility PowerPoint template is the source of truth — do not invent a new visual identity.

The goal is considered, contemporary Nordic business design: calm, structured, premium and useful. Slides should feel like Intility: restrained, precise and visually confident. They must not become generic AI-consulting slides.

A dark deck does not mean plain white bullet text on a dark background. Create variation through layout, hierarchy, cards, accent blocks, typography, whitespace and content-specific structures.


## 1. Content and language

- Write in Norwegian unless explicitly told otherwise.
- Use clear, professional, understated business language.
- Avoid sales language, slogans, exaggerated claims and generic AI phrases.
- Do not invent facts, numbers, customer examples, product names, internal policies or commitments.
- If information is missing, use placeholders such as [sett inn tall], [sett inn kunde] or [avklar].
- Keep customer-sensitive information out of AI-generated content unless explicitly provided and approved.
- All output must be manually quality assured before use.

Slide text should be concise. Use speaker notes for explanation.

---

## 2. Slide format and visual mode

- Use 16:9 widescreen by default.
- Use dark background `#09192B` as the dominant base for almost all slides.
- Light backgrounds `#EAF2FA` are exceptional and should only be used when explicitly requested or when there is a clear functional reason, such as readability of a dense table.
- A normal Intility deck should be dark overall, but not visually repetitive.

Dark-mode variation should come from:

- Accent-filled cards
- Accent-filled panels
- Dark navy content surfaces
- Asymmetric layouts
- Split compositions
- Varied card sizes
- Strong typography
- Full-slide accent section dividers
- Tables and matrices adapted for dark mode
- Hero numbers or short statements
- Process blocks
- “So what” boxes
- Highlighted implications

Do not solve visual monotony by switching to light backgrounds. Solve it with better structure.

---

## 3. Design direction

Create slides that help the audience understand the message faster.

Good slides should have:

- One clear message
- One dominant visual idea
- Strong hierarchy
- Generous whitespace
- Clear grouping
- Content-specific layout
- Restrained but meaningful use of accent color

Avoid decoration for decoration’s sake. Every visual element must support meaning, hierarchy, grouping or emphasis.

The design should be calm, but not dull. It should be varied, but not noisy.

---

## 4. Layout choice requirement

Do not default to title + white bullet list.

For every slide, first identify the content type and choose a layout that fits the message.

Use this decision logic:

- Key message / insight → large headline + 2–3 supporting cards
- Strategic point → short statement + implication cards
- Problem / challenge → tension statement + evidence or consequences
- List → bullets only if a list is genuinely the clearest structure
- Alternatives → side-by-side comparison cards
- Before / after → two-panel contrast
- Process → 3–5 step flow using filled blocks
- Timeline / roadmap → grouped phases, not generic arrow chains
- Risks → risk cards, risk/impact matrix or risk/mitigation table
- Responsibilities → ownership cards or RACI-style matrix
- Operating model → layered model, grouped cards or process structure
- Metrics / numbers → hero stat, KPI cards or simple chart
- Recommendations → prioritized cards or numbered decisions
- Summary → numbered recap, “so what” cards or decision summary
- Dense information → table, matrix or appendix-style structured slide

If a slide has more than one main idea, split it into multiple slides.

---

## 5. Bullet discipline

Traditional bullet slides are allowed, but they are not the default.

Rules:

- No more than 20–25% of a normal deck should be simple bullet-list slides.
- Do not create long white bullet lists on dark background unless explicitly needed.
- If a slide has more than 5 bullets, restructure it into cards, groups, table or multiple slides.
- Bullets should be short and parallel in structure.
- Never use bullets as a substitute for thinking about layout.

Before using bullets, consider whether the content is better expressed as:

- 2–4 cards
- Comparison
- Process
- Timeline
- Matrix
- Risk/mitigation structure
- Key message + supporting proof points
- Summary cards
- Hero number + implication

---

## 6. Deck-level rhythm

Design the deck as a sequence, not as isolated slides.

A typical deck should include a balanced mix of:

- Title slide
- Agenda or framing slide
- Key message slides
- Card-based slides
- Comparison slides
- Process or timeline slides when relevant
- Table or matrix slides when useful
- Section dividers for longer decks
- Summary or recommendation slide

Avoid making consecutive slides look structurally identical.

Across any 4-slide sequence, vary at least two of the following:

- Layout
- Card structure
- Typography scale
- Dominant visual element
- Accent color
- Background treatment within dark mode
- Use of table/matrix/process/card composition

Variation should feel intentional, not random.

---

## 7. Headlines

Slide titles should communicate the point, not just name the topic.

Prefer:

- “Tre grep reduserer operasjonell risiko”

Instead of:

- “Risiko”

Prefer:

- “Modellen gir bedre skalering uten tilsvarende økning i kompleksitet”

Instead of:

- “Skalerbarhet”

Rules:

- Keep titles short.
- Make them useful.
- Avoid vague headings like “Overview”, “Status”, “Summary” unless paired with a clear point.
- Use speaker notes for nuance and explanation.

---

## 8. Colors

Use only the Intility palette unless another color already exists in the official template.

Palette:

- Base dark: `#09192B`
- Base light: `#EAF2FA` — exceptional use only
- Brand/default accent: `#0DF2D7`
- Green/success: `#00F497`
- Yellow/warning/attention: `#FFEB95`
- Red/critical/error: `#FF4B33`
- Pink/thematic: `#FF33AE`
- Purple/thematic: `#A075FF`

Rules:

- Use one dominant accent per slide.
- Rotate accent colors across the deck based on theme, section or content type.
- Do not default to `#0DF2D7` on every slide.
- A typical deck should use at least 3 accent colors across the full sequence if the content allows it.
- Keep accent use consistent within a theme.
- Use strong contrast between text and background.
- Use accent colors as filled cards, panels, blocks, badges or large typography — not as thin decorative lines.

Semantic color use:

- `#00F497` → success / positive / completed
- `#FFEB95` → warning / attention / dependency
- `#FF4B33` → critical / error / high risk
- `#0DF2D7` → brand / information / default
- `#FF33AE` and `#A075FF` → thematic separation only, not status

When the slide is not status-related, non-status accents are good choices for visual variation.

---

## 9. Typography

Use only these fonts:

- Satoshi Intility
- Satoshi Intility Light
- Satoshi Intility Medium

No other fonts.

Recommended sizes:

- Hero number / display: 44–72pt, Medium
- Large insight headline: 38–56pt, Medium
- Slide title: 28–32pt, Medium
- Section heading: 20–24pt, Medium
- Body: 14–16pt, Light
- Minimum body size: 10pt, but prefer 14pt or larger
- Caption / footnote: 11–12pt
- Tag / badge: 10–11pt, Medium

Use typography as a design element. A short, well-written phrase in large type can carry an entire slide.

Avoid dense text. If the slide feels text-heavy, split it or move explanation to speaker notes.

---

## 10. Tags, badges and pills

Use tags sparingly for structure, not decoration.

Rules:

- Text in UPPERCASE
- Maximum 1–2 words
- Satoshi Intility Medium
- Compact vertical padding
- Use character spacing if available
- Use pill/capsule shape with rounded corners
- Do not place a tag on every card unless it adds real meaning

Examples:

- ANBEFALING
- RISIKO
- NESTE STEG
- AVKLARES
- PRIORITET 1

---

## 11. Border radius

All rectangular shapes used as text boxes, cards, containers or content surfaces must have rounded corners.

This is critical.

Rules:

- Text boxes, cards, containers and content surfaces: rounded corners.
- Default radius: Bifrost radius-s / approx. 8px.
- Pills, capsules, tags and badges: fully rounded.
- Sharp corners are reserved only for tables, image boxes and full-width background bands.
- Do not mix radius values within the same component group.
- Plain text directly on the slide background does not need a container.
- Any shape with fill, border or container function must have rounded corners.

If using pptxgenjs, define constants at the top of every script:

```js
const RADIUS_DEFAULT = 0.08;
const RADIUS_PILL = 0.5;
```

In pptxgenjs, every filled text box should use `pptx.ShapeType.roundRect` with `rectRadius` set. Do not use default sharp rectangles for content containers.

---

## 12. Spacing

Use the Bifrost 8px grid.

Approximate spacing in inches:

- `0.08"` — tightly related elements
- `0.17"` — within a group
- `0.25"` — between groups
- `0.33"` — between sections
- `0.42"` — slide margins / page padding

Rules:

- Minimum slide margin: `0.42"`.
- Do not place text close to slide edges.
- Use generous whitespace.
- Align elements deliberately.
- Keep related items visually grouped.
- Avoid cramped cards and crowded tables.

If a slide becomes crowded, reduce content, split the slide or move detail to notes.

---

## 13. Borders and shadows

- Prefer separation through spacing, fills and background contrast.
- Border default: 0.75pt, dimmed grey or subtle navy.
- Never use pure black borders.
- Avoid borders unless they clarify structure.
- No shadows by default.
- If shadows are used, apply them only to cards, never to text.
- Shadows must be subtle: max 4pt blur, 10–15% opacity.

---

## 14. Composition

Use existing template layouts where possible.

General rules:

- One visually dominant element per slide.
- Use asymmetry where natural.
- Avoid perfectly centered generic layouts unless the slide is a title, section divider or hero statement.
- Use cards and panels to group meaning.
- Use accent fills and blocks, not decorative strokes.
- Prefer fewer, stronger elements over many small elements.
- Avoid placing all content in the upper-left by default.
- Avoid creating the same slide structure repeatedly.

A slide should still work if viewed from the back of a room: the main point must be obvious.

---

## 15. Recommended slide patterns

Use these as the main pattern library.

### Default / workhorse patterns

Use freely when the content fits:

- Title slide
- Agenda — numbered items, not bullets
- Key message slide — large headline + 2–3 supporting points
- Card grid — 2–4 cards with varied emphasis
- Asymmetric card layout — one dominant card plus smaller supporting cards
- Comparison — side-by-side cards or table
- Before / after contrast
- Process flow — 3–5 steps using filled blocks
- Timeline / roadmap — grouped phases
- Risk / mitigation slide
- Responsibility matrix
- KPI or metric cards
- Summary — numbered recap or card-based recap

### Occasional patterns

Use when the content clearly benefits from it:

- Hero stat
- Split layout, 60/40 or two-thirds/one-third
- Full accent panel with supporting explanation
- Matrix, e.g. impact/effort or risk/likelihood
- Short pull statement without decorative quote marks
- Section divider with strong typography

### Rare / exceptional patterns

Use only when genuinely appropriate:

- Quote / pull text with attribution
- Light-background slide
- Image-led slide
- Complex diagram
- Dense appendix slide

---

## 16. Tables, matrices and charts

Tables and matrices are allowed when they make the content clearer.

Rules:

- Keep tables simple and readable.
- Use dark-mode table styling unless a light table is explicitly required for readability.
- Use clear hierarchy in header, rows and emphasis.
- Avoid tiny text.
- Highlight only the most important cells.
- Do not overuse gridlines.
- Use semantic colors carefully.
- Charts should be simple, legible and based only on provided data.

Do not invent numbers. Use placeholders if data is missing.

---

## 17. Process and timeline design

Process slides should not look like generic AI diagrams.

Avoid:

- Equal-sized boxes connected by equal arrows
- Excessive arrows
- Decorative lines under numbers
- Icon-in-circle repetition
- Overly symmetrical consulting-style flows

Prefer:

- Grouped phases
- Staggered steps
- Filled blocks
- One larger current or critical step
- Short step labels
- Concise implications
- Clear start/end logic only when needed

Use arrows only when direction or dependency must be explicit.

---

## 18. AI-generated tropes to avoid

Avoid anything that looks like generic AI-generated presentation design.

Do not use:

- Thin accent lines or colored stripes along card edges
- Decorative horizontal lines under numbers
- Three identical cards in a row with the same internal structure
- Sharp-cornered rectangles as content containers
- Oversized decorative quote marks
- Repeated icon-in-circle patterns
- Equal boxes connected by generic arrows
- Gradients
- Glassmorphism
- 3D effects
- Fake UI screenshots
- Stock photo aesthetics
- Large decorative illustrations
- Animations added for effect

The common problem is decoration pretending to be design. Avoid it.

---

## 19. Logo, icons and graphics

- Do not recreate, redraw, recolor, stretch, crop or modify the Intility logo.
- Use the logo only through the existing template placement.
- Icons are optional and should only be used when they clarify content.
- Use the icon style already present in the template or approved Slidehub assets.
- Do not mix icon styles.
- Do not use generic AI-generated icons.
- Avoid decorative illustrations unless explicitly requested and brand-approved.

---

## 20. Speaker notes

Add speaker notes for every slide.

Rules:

- 2–4 sentences per slide.
- Plain Norwegian.
- Explain the main point.
- Do not repeat the slide text word-for-word.
- Include nuance, assumptions or context that does not fit on the slide.

---

## 21. Creation workflow

For each deck:

- Understand the purpose, audience and decision context.
- Create a simple narrative flow before designing slides.
- Assign each slide one clear message.
- Choose layout based on content type, not habit.
- Build slides using the Intility template and palette.
- Review slide sequence for variation and rhythm.
- Remove unnecessary text and decoration.
- Add speaker notes.
- Run final quality check.

For each slide, ask:

- What is the main point?
- What should the audience remember?
- What layout best explains this?
- Is this just a bullet slide because that was easiest?
- Can the same content be clearer as cards, comparison, process, matrix or hero statement?

---

## 22. Final quality check

Before finishing, verify:

- The Intility template is used consistently.
- Dark background dominates the deck.
- Light backgrounds are used only in justified exceptions.
- The deck does not default to white bullet lists on dark background.
- No more than 20–25% of slides are simple bullet slides unless explicitly requested.
- Each slide has one clear message.
- Each slide has one dominant visual idea.
- Layouts are chosen based on content type.
- Consecutive slides do not look structurally identical.
- Accent colors are rotated across the deck and used meaningfully.
- Accent colors are used as fills, blocks or emphasis — not thin decorative strokes.
- Status colors are used semantically.
- Typography hierarchy is clear.
- Text is concise and readable.
- Minimum font sizes are respected.
- Spacing follows the Bifrost 8px grid.
- Slide margins are respected.
- Every card, text box and content container has rounded corners.
- There are no sharp-cornered text containers.
- Tables, charts and matrices are readable.
- No generic AI-slide tropes are present.
- No invented facts, numbers or claims are included.
- Speaker notes are included.
- The deck would pass internal Intility quality review.

Final test:

Would this deck feel like a calm, well-designed Intility business presentation — not a generic AI-generated slide deck?

If not, revise the layout, reduce text and improve structure before finalizing.
